## Project Name

Mlimi Market

## Project Mission

Mlimi Market is an online marketplace for farm products. It connects farmers who list agricultural produce with buyers who want to purchase that produce.

The platform should make it easy for:

- Farmers to register, add products, manage products, receive orders, and message buyers.
- Buyers to register, browse products, add products to cart, place orders, track orders, and message farmers.

This is currently an MVP marketplace without online payment processing.

## Prisma 8 Workflow (Important)

This project uses **Prisma 8**, not classic Prisma 7.

### Key concepts

- Schema source of truth → contract (usually `src/prisma/contract.prisma` or equivalent)
- Emitted artifacts → `contract.json` + TypeScript types
- Client → `db` (imported from `src/prisma/db` or the path generated by `orm init`)
- Queries use the schema namespace: `db.orm.public.ModelName`
- Database must be **signed** so the runtime can verify the contract

### Common commands

```bash
# Emit contract after any schema change
npx prisma@latest contract emit

# Sign the database (first time or after contract change)
npx prisma@latest db sign

# Verify marker + schema
npx prisma@latest db verify

# Plan a migration
npx prisma@latest migration plan --name descriptive_name

# Apply migrations
npx prisma@latest db migrate

# For brand-new empty DB (rare in this project)
npx prisma@latest db init
```
### Query style (Prisma 8)
```ts 
import { db } from "@/prisma/db"; // adjust path as needed

// High-level ORM API
const products = await db.orm.public.Product
  .where({ status: "ACTIVE" })
  .select("id", "title", "price")
  .limit(20)
  .all();

// Low-level SQL builder when needed
const plan = db.sql.public.product
  .select("id", "title")
  .limit(20)
  .build();
const rows = await db.runtime().execute(plan);
```
Do not use classic Prisma Client patterns (prisma.user.findMany, $connect, $disconnect, etc.).

## Business Rules

1. Only authenticated farmers can create products.
2. Only the product owner can edit or delete their product.
3. Only authenticated buyers can place orders.
4. Buyers cannot order inactive, hidden, or sold-out products.
5. Buyers cannot order more than available stock.
6. Order totals must be calculated on the server.
7. Never trust client-side price calculations alone.
8. Store product price and title snapshot in order items.
9. Farmers should only see orders that contain their products.
10. Users should only see messages they are part of.
11. Admin can moderate products and users.
12. All forms must show validation errors.
13. All destructive actions should ask for confirmation.
14. Use loading states for async actions.
15. Use success and error toast notifications.
16. Do not expose other users’ private data.
17. Do not expose server secrets to the client.
